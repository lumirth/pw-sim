C → LLVM → WebAssembly → your browser ●
NATIVE SOURCE EXPLORER

MainTick



Recompiled. Instrumented. Playable.
The application logic is the release’s reconstructed C, compiled by native LLVM/Clang into WebAssembly. There is no H8 CPU interpreter, ROM execution loop, or JavaScript implementation of the game.
RECONSTRUCTED C35 source files→CLANG / LLVMwasm32 target→WEBASSEMBLY
The browser supplies clocks, buttons, an LCD surface, EEPROM storage, simulated acceleration, and sound. The port retains 16-bit data layouts and converts EEPROM records at the storage boundary.
Device time runs at 1×: the foreground cadence is 16 Hz, display requests are 4 Hz, and the RTC advances once a second. Background tabs pause. This is an event-timed source port, not a claim of H8 instruction-cycle equivalence.
The untouched starting snapshot was rebuilt with Renesas and matched all 49,152 retail bytes. That establishes the source baseline; the browser port deliberately changes its target and hardware interfaces.
The six futures clone native memory and execute the compiled routines independently. Source counters, FFT values, RAM bytes, and LCD pixels are read from those executions. These tools exploit direct C integration; equivalent ideas could also be built into a sufficiently instrumented emulator.
The physical simulation is illustrative, not a calibrated aerodynamic model. IR currently follows an offline timeout path. Hardware manufacturing tests and unrestricted EEPROM images are not qualified.
